**Тема:** Модульне тестування програмного забезпечення. Еквівалентне розбиття та аналіз граничних значень.

## 1. Реалізація програмного модуля

На основі UML-моделі (з ЛР 02) системи управління завданнями було створено програмний модуль `taskmanager` мовою Go.

Модуль містить 3 ключових методи з нетривіальною логікою (наявні умовні конструкції, цикли, обробка виняткових ситуацій):

1. **`AddUserToTeam`** — додавання користувача до команди з перевіркою на дублювання (цикл `for` та умова `if`). Повертає кастомну помилку `ErrUserAlreadyInTeam`.
2. **`RemoveUserFromTeam`** — видалення користувача з команди. Використовує цикл для пошуку індексу, маніпулює зрізом масиву та повертає виняток `ErrUserNotInTeam`, якщо користувача немає.
3. **`AutoUpdateTime`** — автоматичне оновлення залишкового часу завдання. Має умову на від'ємний плин часу (`ErrNegativeElapsedTime`) та логіку фіксації часу на нулі, щоб таймер не став від'ємним.

## 2. Проєктування тестів (Класи еквівалентності та граничні значення)

Для кожного методу були визначені класи еквівалентності (EP) та граничні значення (BVA).

| Метод | Вхідні параметри | Клас еквівалентності (EP) / Граничне значення (BVA) | Очікуваний результат | Тип тесту |
| :--- | :--- | :--- | :--- | :--- |
| `AddUserToTeam` | Користувача немає в команді | **EP:** Додавання в пусту/не пусту команду | Додано успішно (`nil`) | Позитивний |
| `AddUserToTeam` | Користувач вже є в команді | **EP:** Дублікат | Помилка `ErrUserAlreadyInTeam` | Негативний |
| `RemoveUserFromTeam` | Видалення існуючого юзера | **BVA:** В команді залишився 1 користувач (границя масиву: перехід до порожнього) | Успішне видалення (`nil`) | Позитивний |
| `RemoveUserFromTeam` | Видалення неіснуючого юзера | **EP:** Користувача немає у списку | Помилка `ErrUserNotInTeam` | Негативний |
| `AutoUpdateTime` | Негативний плин часу | **EP:** Від'ємне значення `elapsed < 0` | Помилка `ErrNegativeElapsedTime` | Негативний |
| `AutoUpdateTime` | Звичайний плин часу | **EP:** Додатне значення, що не вичерпує таймер | Час зменшено успішно (`nil`) | Позитивний |
| `AutoUpdateTime` | Час дорівнює залишковому | **BVA:** Зменшення часу рівно в `0` | Залишковий час = `0`, помилок немає | Позитивний |
| `AutoUpdateTime` | Час більше залишкового | **BVA:** Зменшення нижче `0` (границя фіксації на `0`) | Залишковий час фіксується на `0` | Позитивний |
| `SubscribeUser` | Новий користувач | **EP:** Підписка на завдання | Підписано успішно (`nil`) | Позитивний |
| `SubscribeUser` | Юзер вже підписаний | **EP:** Дублікат | Помилка `ErrUserAlreadySubscribed`| Негативний |

## 3. Набір модульних тестів (Патерн AAA)

Для тестування було використано вбудований фреймворк Go `testing`. Усі тести написані за патерном AAA (Arrange — Act — Assert).

Приклад одного з тестів із коментарями:

```go
// BVA: Позитивний. Зменшення нижче 0 (має зафіксуватись на 0).
t.Run("Decrease below zero - Positive BVA", func(t *testing.T) {
    // Arrange (Підготовка)
    timer := &Timer{RemainingTime: 5 * time.Second}

    // Act (Дія)
    err := timer.AutoUpdateTime(10 * time.Second)

    // Assert (Перевірка)
    if err != nil {
        t.Errorf("Unexpected error: %v", err)
    }
    if timer.RemainingTime != 0 {
        t.Errorf("Expected 0, got %v", timer.RemainingTime)
    }
})
```
